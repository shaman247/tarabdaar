# Tarabdaar

Tarabdaar is an expressive instrument with an iPad Fret Pad and a Mac sound engine. Touches play continuous pitch, with polyphony, finger vibrato and an optional glide queue. The Mac synthesizes the bowed sarangi String voice, its sympathetic strings, and the plucked Tanpura and Sitar voices. Joy-Con motion and iPad tilt can control expression.

The devices communicate using TLP over USB or BLE-MIDI. CoreMIDI transports the protocol's SysEx frames; sound is generated by the Mac's bundled engines.

## Requirements

- Mac running macOS 13 or later
- iPad running iPadOS 16 or later for touch and motion input
- Xcode with Swift 5.9 or later and the macOS/iPadOS SDKs

The two Swift packages and voice resources are included in this repository. A physical iPad is required to check sensors and the device link; the Mac Fret Pad also supports local mouse playback.

## Build and run

1. Open `Tarabdaar/Tarabdaar.xcodeproj` in Xcode.
2. Select the **TarabdaarMac** scheme and run it on the Mac.
3. Select the **Tarabdaar** scheme, choose the connected iPad, configure signing for that device, and run it.
4. Connect over USB and enable the iPad in **Audio MIDI Setup → Window → Show MIDI Studio**, or connect over BLE-MIDI using the apps' connection controls.
5. Play the iPad's Fret Pad. Edit the scale, tonic and fret arrangement in the Mac's **Fret Pad (⌘3)** tab.

Install both apps from the same revision: they currently require TLP version 26 (half-point fingertip-radius units).

From the repository root, build the Mac app and regenerate the parameter and HTML documentation with:

```bash
./tools/build-mac.sh
```

The build is written to `build/mac-ci`. Research scripts, recordings, render outputs and independent browser projects are local working material, ignored by Git and unnecessary for the native build.

## Checks

```bash
swift test --package-path Packages/SarangiKit
swift test --package-path Packages/TarabdaarCore
./tools/test-full.sh
```

The full guard enables the slow DSP suites and runs timing-sensitive checks serially. Run it before committing kernel, table-builder, parameter or level changes. See [AGENTS.md](AGENTS.md) for development conventions.
