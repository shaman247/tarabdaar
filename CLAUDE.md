## What the instrument is

**Two devices, one link.** An iPad runs the **Fret Pad**, the only playing surface, and streams touches and raw tilt over **TLP** (`Packages/TarabdaarCore/.../Link/`) to a Mac that owns all the sound. Bundle IDs `com.tarabdaar.Tarabdaar` / `com.tarabdaar.TarabdaarMac`; presets are `.tarabdaar`.

**Three voices.** The sarangi **String voice** (`SarangiKit.BowEngine` + the `CBowKernel` C friction kernel) is the default played voice. The **Tanpura** (`TanpuraEngine` + `tanpura_kernel.c`) is the default drone voice and an optional main instrument; the **Sitar** is a second `TanpuraEngine` mounted from `sitar_live.json` (the scale-model role ladder), main-instrument only. Both plucked voices charge the String kernel's sympathetic web through its inject ring.

**The taraf.** The sympathetic strings are modal-jawari rows inside the String kernel (`bow_jt_*`): scale-degree strings on the raga bridge plus a chromatic set with its own level, level norm and evolution (`bow_jtc_gain`/`_norm`/`_evolve`) over the same jawari geometry. Each row radiates the DC-blocked contact force it exerts on its bone plus its termination force at the pin, each unit-matched per row (`JtTables.rowForceScale` / `rowPinScale`, both on the kernel's jt load ABI). The bridge force ENTERS each row through the fitted 0.90 L tap — the one drive shape (`bow_jt_drive_term`, the 0…1 morph to the termination's comb-free mode slope, was **removed 2026-09-03**: under either normalisation it only read as a taraf loudness knob and 0 sounded best; roadmap item 2 in [docs/sarangi.md](docs/sarangi.md)). **2026-09-03: the drive is no longer one-way** — `bow_jt_couple` (0…1, live, **default 0 = byte-null**) returns the rows' own summed **DC-blocked** bridge force, converted back to newtons by `JtTables.rowCplScale` and divided by the bank's total row gain Σ gout, into the played strings' `F` one post-pass block out, so the web loads the bridge, radiates through the body and charges itself on the next tick. **Two traps, both fixed at the cause:** the raw per-row load carries the row's static wrap preload as a DC term, so returning it parks a constant force on the bridge and self-excites the web — that, not the quiescence gate, was why the first cut never went silent (a bowed Sa's 12 s ring parked at −42 dBFS with 0/34 rows asleep; blocked, it truncates with 34/34 asleep); and a row the gate puts to sleep FADES its last returned value out rather than stepping to 0. The knob is **0…1 of a measured safe range** (`BowEngine.jtCoupleFullScale` 0.4 = half the divergence gain), measured on the HEAVY case — a Sa/Pa/Sa′ chord at full expression — because a single note is far more forgiving (roadmap item 3). Guard: `TarafCoupleTests`. A melody-follower row can live-retune to the played pitch. The Strings tab (⌘2) edits the rows; drone buttons and the Joy-Con strum pluck them.

**Mac tabs:** Live ⌘1 · Strings ⌘2 · Fret Pad ⌘3 · Controls ⌘4 · Parameters ⌘5 · FX ⌘6 · Setup ⌘7 · Scope ⌘8 · Taraf ⌘9.

**Not present, by decision** (details and dates in `docs/history/`): the SWAM/hosted-AU voice, the coupled bridge–body network and its FX rack, the linear comb-string taraf web, the Harmonics/Simulator/Chord Pad/String Pad/Pitch Pad tabs, the in-process MIDI note vocabulary and the headless audition pipeline, the fixed sargam naming table, per-string ratio/Hz tuning, the 0.90 L taraf radiation pickup (`bow_jt_tap`), fret linger / auto-vibrato, the legato/portamento allocation laws and the meend smoother, the automatic vibrato LFO, per-row taraf detune. Do not restore any of them on the assumption they were lost.

## Key conventions

- **The wire is TLP, not the MIDI vocabulary.** The iPad streams one latest-wins `PERF_STATE` frame (every touch at f32 fractional-MIDI pitch with an `onsetSeq`, an onset velocity byte and a fingertip `radius` byte, 16-bit tilt ×3, drone mask, strike byte, chord selection); the Mac streams sync events and `JOYCON_STATE` display frames back. Frames tunnel in one SysEx envelope over CoreMIDI — USB first, else **BLE-MIDI** (kept deliberately: its ~11 ms connection interval beats any custom GATT link). `TarabLink` paces sends at 120 Hz on its own queue. **There is no MIDI note vocabulary** — no notes, bends, CCs or MPE anywhere, in-process included; CoreMIDI is only the TLP transport, and `MIDIInput` exists solely to reassemble inbound SysEx. Spec: [docs/midi-and-audio.md](docs/midi-and-audio.md).
- **Almost no shared state.** iPad owns glide and calibration; Mac owns physics, tuning and bindings. The only cross-device state is the one-way pad sync (`SCALE_STATE`, `FRET_ARRANGEMENT`) plus the acted-on `JOYCON_STATE` fields (`connected`, `fieldWarp`, `octave`) and the iPad's chord selection. Do not add shared parameters.
- **The iPad evaluates no mappings.** It streams raw axes; the Mac evaluates `tiltMapping` (`AppController.handleRawTilt` → `applyTiltAxis`). The strike byte feeds the `.strike`/`.acceleration` dimension pair through `evaluateStrikeBlend` (per-note window), never through `applyTiltAxis`; `.fingerAccel` is derived on the Mac from the frame pitches.
- **Packages.** `TarabdaarCore` = cross-platform building blocks (scale, link, config, motion, pad engine, Mac-only `AudioEngine`); `SarangiKit` = the voices and the kernel. Anything used across a package boundary must be `public`, `init` included. `CBowKernel` builds with `-O3` always.
- **ONE parameter registry.** Every knob is a `ParamSpec` in `ParamRegistry.swift` with a `scope` (`.global`/`.perNote`) and an apply strategy (`live`/`rebuild`/`hybrid`); adding a parameter is one entry, and it appears in the Parameters tab, the composite and tilt menus and the docs. The one apply path is `AppController.applyParamToVoice`. Ranges live in the registry; `Config.swift` holds system constants only. The Parameters tab and `docs/parameters.md` render the same `ParamScope`/`ParamTiming` strings — never derive display timing from `apply` alone.
- **ONE scale, ONE tonic.** `AppController.pitchPad` owns them; the tonic is set in Hz on the Fret Pad tab (the app's only Hz input). Frets, tarab rows and drones are scale-degree references; the tarab pool is pitch-sorted with one string per pitch (`InstrumentState.normalizeStrings`). Every pitch is named by the scale's own labels (`scaleLabel(degree:)` / `scaleLabel(forRatio:)`, `ScaleDegrees.swift`); concert note names label absolute Hz only. Use `scale.frequency(for:)`, never a hardcoded 12-TET formula; interpolate pitch in `log2(freq)`.
- **One touch = one string.** Each touch gets a u16 wire id and full-resolution pitch; the mapper allocates `bow_live_poly` gut strings on one bridge, keyed by that id. Every note-on mounts a fresh string; within a note the pitch follows the finger at wire rate — vibrato and meend are played, not synthesized, or, for a trailing note, the **fingertip-flatten ease** (2026-09-04, TLP v13): the touch record's never-read `pressure` byte became `radius` (`UITouch.majorRadius` pt × 4, record size unchanged), and the shared `TouchFlattenDetector` law (median onset baseline over 150 ms; flattened at `Config.touchFlattenStepPt` = 3 pt above it, released at step/2 — a BINARY signal, the radius is far too coarse for an axis) drives `FlattenVibrato` → `BowControlMapper.setVibrato(_:forTouch:)`, easing that ONE note's `bow_vib_cents` depth 0→1 over 2 s while flattened and back over 0.5 s. Vibrato depth is PER SLOT now; the global setter is "set all". Depth 0 is byte-null (parity untouched), and this is NOT the removed automatic vibrato LFO — nothing moves unless the player flattens a fingertip. The **glide queue** (`GlideSequencer`, `ctl_glide_*`, off by default) sits above allocation and turns overlapping onsets into glissando waypoints.
- **Threads.** Producers write `OutboundPlayState`; the link paces the wire. The audio thread runs the source render blocks only. Hot paths use `cachedParamValue(for:voiceIndex:)`, never the dictionary lookup. SwiftUI updates on the iPad are throttled to ~15 Hz.
- **`InputDimension`** is the dimension enum (avoids `Foundation.Dimension`). **`PadLayout`'s non-fret cases must stay** — the sync blob encodes the layout by raw value.

## Building and testing

```bash
./tools/build-mac.sh                       # Mac build + docs/parameters.md + docs/html
cd Packages/TarabdaarCore && swift test    # fast loop, seconds
cd Packages/SarangiKit && swift test       # kernel lockstep + ByteNullContractTests
tools/test-full.sh                         # the full guard: gated DSP suites, phase 2 serial
```

The DSP render suites (`TarafRemovalParityTests`, `RealtimePerformanceTests`, `RebuildCostTests`, `ZipperTests`, `LiveParamPushTests`, `TarafCoupleTests`) skip without `TARABDAAR_SLOW_TESTS=1`; `tools/test-full.sh` is required before committing any kernel, table-builder, parameter or levels change (phase 2 is skipped when phase 1 fails). The guard set is deliberately small — **about 77 tests, 10 in SarangiKit and 67 in TarabdaarCore** — and a test earns its place only by pinning a contract that would break silently (codec/persistence compatibility, the allocation law, a threading repro, a byte-null path, parity), a stability bound, or a lockstep with a golden: one render hash pins the shipped sound, `ByteNullContractTests` pins that every "0 = off" path is bit-null at rest, `TarafCoupleTests` pins that the coupled web cannot run away, `ControlCacheConcurrencyTests` pins that the live apply path survives concurrent writers, and the logic suites pin invariants nothing else would catch. Do not add a test that re-covers another one, asserts a calibration number, or checks that a setter stored a value. When you change the sound, bless the hash on purpose; when you add an optional path, add a contract case. Test doc comments are one line — no dates, no history: the ear judges the sound, git holds the story.

`tools/install-hooks.sh` installs a pre-commit hook that runs the full guard when a kernel, builder, parameter, artifact or DSP-test file is staged and the fast loop otherwise (`git commit --no-verify` skips it once).

The iOS target builds with `xcodebuild -scheme Tarabdaar` against an iPad simulator (`-showdestinations` lists names). Sensors and MIDI need a physical device. Adding a file to an Xcode target: the `add-xcode-file` skill (files under `Packages/` need nothing).

## Sound design

The physics ship fitted in `bowed_string.json`; Tarabdaar edits values, it does not re-fit. Parameters tab (⌘5) for every knob; Strings tab for the taraf rows; Controls tab for tilt bindings and composites; FX tab for the four-insert rack (off = byte-null). **Levels:** calibration lives in the preset (`bow_live_trim`, `bow_rev_*`), `bow_gain` is the performance master volume, the Mac pads hold the expression axis at the fitted median (0.25), a linked-stereo limiter rides the end of the chain, and `bow_jt_norm` / `bow_bal` / `bow_jt_cap*` shape the taraf against the voice. Presets are one `TarabdaarPreset` document covering the whole rig, saved by name into the app-managed library. To change the shipping default, edit `bowed_string.json` or the tarab builders and re-bless the parity hash deliberately.
