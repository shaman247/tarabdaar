## What the app is now

**2026-08-13: the instrument is named Tarabdaar** (renamed Starpad → TarabPad on 2026-08-12, then → Tarabdaar the next day, before anything shipped under the interim name), identity included: bundle IDs are `com.tarabdaar.Tarabdaar` / `com.tarabdaar.TarabdaarMac`, presets are `.tarabdaar`, and the old Tarab tab is now the **Strings** tab (same ⌘2; "tarab" remains the term for the sympathetic strings themselves). `LegacyMigration` (TarabdaarCore, called first thing in `TarabdaarMacApp.init`) migrates an old install once — Starpad-era or the one-day TarabPad build: moves the newest surviving `Application Support/{TarabPad,Starpad}` folder → `Tarabdaar`, renames `.starpad`/`.tarabpad` (and `map`) presets, and imports the newest surviving legacy defaults domain (`com.tarabpad.TarabPadMac`, else `com.starpad.StarpadMac`) with the `starpad.`/`tarabpad.` key prefixes mapped to `tarabdaar.` — so the remaining `starpad`/`tarabpad` strings in `LegacyMigration.swift` and `PresetLibrary.swift` are deliberate, not a missed rename. The iPad side cannot migrate across its bundle-ID change (sandboxed container) — moot since 2026-08-13: the iPad-side 7-point calibration was deleted — the iPad streams raw attitude, and the Mac's guided ARM calibration (rest + 3 sweeps, iPad-only; the same-day wrist/Joy-Con half was removed) is the app's single tilt calibration. Historical names in docs/memory (`StarpadDSP`, the deleted package) keep their original spelling.

**Three voices, one playing surface.** The sarangi **String voice** (`SarangiKit.BowEngine` + the `CBowKernel` C friction kernel) is the played voice, and the **Fret Pad** is the only playing surface. **2026-08-04: the TANPURA voice joined it** (`SarangiKit.TanpuraEngine` + `tanpura_kernel.c`, ported from Sarangi Live's r7 modal-contact tanpura — see [docs/tanpura-voice.md](docs/tanpura-voice.md)): a second source node beside the String voice's, the **default drone voice** (the Fret Pad drone buttons pluck it; Strings tab's Voice picker restores the legacy jt swell) and the **optional main instrument** (Live tab's Instrument picker — fret notes become plucks at the exact bent pitch; 2026-08-05: post-onset glides live-retune the ringing string kernel-side and note-off fast-releases it, `tp_rel_t60`; 2026-08-21: its output also charges the sarangi jt taraf through the sitar's inject ring, `tp_taraf` — per-source tap gains, the kernel gain is just the shared arm). It is a NEW port, unrelated to the StarpadDSP tanpura deleted 2026-07-23 (still listed below; do not confuse the two). **2026-08-19/20: the SITAR voice joined as the third instrument** (see [docs/sitar-voice.md](docs/sitar-voice.md)): a second `TanpuraEngine` mounted from `sitar_live.json` — **the SCALE-MODEL ROLE LADDER** (v3, 2026-08-20): per-third-octave roles, each a geometrically scaled copy of the fitted C3 tanpura string (same materials → B constant, t60 ∝ 1/f, scaled jawari+jiva, kc·s^(α−1), `radByMode` scaled-body radiation per mode INDEX) — the principled physics behind the ear-picked octave-grid varispeed prototype (C3→C4/C3→C5 cells; v2's one-day `tapeRefF`/`srcBodyFIR` law switches are DELETED, the ladder's optional per-role fields replaced them and the tanpura's nil path is byte-identical; v1's bare-bone fit to `sitar1.wav`'s 561 series was rejected by ear — do not resurrect either, though sitar1's decomposition stands: a played string + a *growing* sympathetic halo). Simulability bounds are bench-set (no mMin for ladder roles, per-rung zoneW, rampCycles 1.0 is a STABILITY law, 1.5 kHz mount cap) — read the doc before touching any of them. Main-instrument only (Live tab picker; **the String bowed voice stays the default**; shares the tanpura's whole pluck/bend/release path), with the **sarangi jt web as its sympathetic taraf**: the sitar node's output feeds the String kernel's inject ring (`bow_poly_jt_inject_*`, `st_taraf`; byte-null when unused — parity untouched). It too is NOT a revival of the StarpadDSP sitar (deleted with its tab 2026-07-23; that fit targeted the deleted harmonic model). Mac tabs: **Live ⌘1 · Strings ⌘2 · Fret Pad ⌘3 · Controls ⌘4 · Parameters ⌘5 · FX ⌘6 · Setup ⌘7**. (The FX tab, 2026-08-01, is a NEW four-insert rack inside `BowEngine` — see [docs/fx.md](docs/fx.md); it is unrelated to the FX tab deleted 2026-07-24 with the coupled network, which must stay dead.)

## Key Conventions

- **Two devices, one link, almost no shared state — and the wire is TLP, not the MIDI vocabulary (2026-08-14).** The iPad↔Mac protocol is **TLP** (`Packages/TarabdaarCore/.../Link/`): the iPad streams one latest-wins `PERF_STATE` frame (ALL touches at full-resolution f32 fractional-MIDI pitch with per-touch `onsetSeq` and — TLP v4/v5, 2026-08-18 — flag-gated `posY` (fret-band y, the linger recharge travel axis) + `fretY` (OUTWARD within the HOME fret's extent — 0 at the end toward the pad's centre-line, 1 at the outer end, oriented by the surfaces via `fretOuterEndIsTop`; the auto-vibrato ceiling axis, dead over the inner `bow_avib_dead`=0.7 of the fret, marked by the frets' wavy outer tails; unsnapped onsets carry none and get no auto-vibrato) bytes feeding the Mac-evaluated fret-linger/auto-vibrato (`bow_linger_*`/`bow_avib_*`; y-less producers keep legacy behavior), 16-bit tilt ×3, drone mask, and — TLP v6, 2026-08-23 — the `strike` byte (the accelerometer strike-scale envelope, 200 Hz fast-attack/~150 ms-decay tracker on the shared `strikeScale01` law) — atomic; touch lifecycle is IN the frame: absence = note-off, new onsetSeq = retrigger) plus reliable events; the Mac streams sync events + `JOYCON_STATE` and `LINGER_STATE` display frames back (the latter, v5: the per-touch linger envelopes as ACTUALLY evaluated, ~20 Hz, wire-id keyed — the iPad's touch overlay draws them and computes nothing). Frames tunnel in the SINGLE SysEx envelope `F0 7D 10 <sender role> <7-in-8 packed> F7` (the role byte lets each side DROP its own traffic echoed through a MIDI loop — IAC/patchbay/dual-transport; a looped hello must never mark the link up) over the CoreMIDI transports — USB session wired-first, the **BLE-MIDI session** otherwise (kept deliberately: Apple grants BLE-MIDI a privileged ~11.25 ms connection interval; a custom GATT link floors at 15 ms, so replacing the bearer would REGRESS wireless latency — do not "upgrade" to CoreBluetooth without measured parity). `TarabLink` paces sends at 120 Hz on its own off-main queue (≤1 fresh state frame per tick, events never dropped, 250 ms heartbeat, 1.5 s staleness → `LinkIngest.linkDidDrop` kill path, ping/pong RTT in Console `TarabLink:` lines). MPE note+bend, tilt CC pairs and per-message SysEx are OFF the wire; the MIDI vocabulary survives **in-process only** (auditions `mapper.midi()`, external controllers, the tanpura pending-pluck) — the parity substrate, do not delete. iPad owns glide/calibration; Mac owns the String physics, tarab tuning, composite/tilt bindings. **Do not introduce shared params** beyond pad sync — if a feature lives on one side, all its state lives on that side.
- **Pad sync, Mac → iPad, one-way, over TLP events.** `SCALE_STATE 0x10` / `FRET_ARRANGEMENT 0x11` carry the SAME v4/v6 binary blobs the legacy SysEx did (codecs split `encodeBlob`/`decodeBlob`; base64 died; iPad UserDefaults persistence byte-identical — no migration). **These are the ONLY cross-device state.** The Joy-Con display rides `JOYCON_STATE` (axes display-only; flags bit 2 `connected` is the one acted-on bit — drone buttons hide while a Joy-Con is attached; the heartbeat floor delivers its edges, no force-resend dance). Legacy subtypes 0x01/0x03/0x05 are retired (decode fallback kept one release in `ScaleSyncReceiver.finalize`); 0x02/0x04 stay dead. The iPad has no scale editor and its tonic is read-only. Wire spec: [docs/midi-and-audio.md](docs/midi-and-audio.md).
- **The iPad evaluates no parameter mappings.** It streams only raw sensor axes — 16-bit tilt fields plus (2026-08-23) the `strike` envelope byte in every `PERF_STATE` frame (atomic with pitch; `TiltAxisWire` CC pairs survive in-process for audition scores); the Mac evaluates its own `tiltMapping` (`AppController.handleRawTilt` → `applyTiltAxis`). The strike byte feeds the **`.strike`/`.acceleration` dimension PAIR** (split 2026-08-23): one measurement, blended per bound target by time since the note started — (1−w)·Strike + w·Accel over a PER-NOTE window (`ctl_strike_window`, .live, def 2 s — intercepted in applyParamToVoice, relayed to the iPad scope fade via JOYCON_STATE v7) (`StrikeBlendWindow`: newest-sounding-note rule, releases fall back to the survivor's un-reset age; unbound sides read as the target's default) — evaluated in `AppController.evaluateStrikeBlend` + a 30 Hz weight timer, NEVER through `applyTiltAxis` (double-apply). Both UNIPOLAR: binding curves read silence at x 0. `NoteManager` on the iPad is just the 60 Hz tilt sampler writing into `OutboundPlayState` — its keyboard/glide/voice MIDI paths stay idle, alive only for audition `noteOn`/`glide` scripts.
- **TarabdaarCore package** (`Packages/TarabdaarCore/`) — cross-platform building blocks (`Scale`, `MIDIEngine`, `MIDIInput`, the `Link/` TLP stack, `Config`, `MotionSource`, `CalibrationData`, `PitchPadEngine`, `NoteManager`, Mac-only `AudioEngine`). `PitchPadEngine` has two inits: `init(audio:)` (Mac — own `OutboundPlayState` → `LocalLinkPump` → `LinkIngest`, in-process) and `init(state:)` (iPad — writes into the app-wide `OutboundPlayState` that `TarabLink` paces onto the wire). **Anything used outside the package must be `public`** — including `init`.
- **SarangiKit package** (`Packages/SarangiKit/`) — the voices: the C friction kernel, its table builders, the control mapper and the tarab document, plus (2026-08-04) the **Tanpura voice** (`Tanpura/`, `tanpura_kernel.c` in the same `-O3` C target, its fitted `tanpura_live.json`; ported from Sarangi Live AFTER the link was cut — it too has no upstream now, except that its artifact regenerates with the upstream exporter, the RECAL LAW). **It is Tarabdaar's own code now.** It began as a vendored copy of `~/Desktop/sarangi` and was kept synced with it, which is why it carried a coupled bridge–body network, an additive violin voice, a byte-parity MONO kernel and ~3.4 MB of offline goldens that Tarabdaar never played. **The upstream link was cut 2026-07-24** and all of it was deleted; there is no re-vendor procedure, no divergence table and no "fix it upstream" rule any more — **change the DSP here**. What survives is exactly the shipping signal path, and `TarafRemovalParityTests` pins its SHA-256, so an accidental edit to the kernel or the table builders fails loudly.
- **`CBowKernel` builds with `-O3` ALWAYS.** The offline reference dylib is `cc -O3`; a debug kernel runs far below realtime.
- **PARAMETER MODEL — read [docs/parameters.md](docs/parameters.md) before touching any parameter.** There is **ONE registry**: `ParamRegistry` (`Packages/TarabdaarCore/.../ParamRegistry.swift`), a flat list of `ParamSpec` covering every knob. **Adding a parameter = ONE `ParamSpec` entry** — it appears in the Parameters tab, the composite menu, the tilt menu and the docs automatically. Since 2026-08-23 every spec also carries a **`scope`** (`.global` = one shared mechanism / `.perNote` = per-note control state — onset clocks, envelopes, phases, windows; the attack family is onset-captured), and `docs/parameters.md` renders Scope + an honest Timing column (live / in-place / rebuild / hybrid, derived from apply + `inPlaceKeys`) — classify new params deliberately (`testScopeClassificationMatchesTheMechanisms` pins the set). The ONE apply path is `AppController.applyParamToVoice(key, value)` (a non-nil return means the caller must funnel it through the debounced `queueRebuildValues` flush). Tilt targets are `MapTarget` — `.composite(slot:)` or `.param(key:)`, endpoints in native units. Apply strategy (`live` / `rebuild` / `hybrid`) is a routing hint, not a user-facing category: no UI labels it. Behaviour, measurements and traps: [docs/sound-design.md](docs/sound-design.md).
- **ONE centralized scale + ONE tonic (2026-07-25).** `AppController.pitchPad` owns the scale and the tonic (set **in Hz** on the Fret Pad tab — the app's ONLY Hz input; `tonicMidi` + `tonicCents` internally); the Fret Pad frets, the tarab strings and the drones are all scale-degree references resolved against it. Tarab strings are `(degree, octave)` — **no per-string ratio or Hz exists anywhere** (the one non-degree pitch is the Strings tab's **melody follower**, a special sympathetic string that live-retunes kernel-side to the highest played note — `InstrumentState.follower`, default off; see [docs/sarangi.md](docs/sarangi.md)), and **following the scale is unconditional** (the "Follow the Pitch Pad scale" toggle + `autoSyncToScale`/`manualEdits` were removed 2026-07-25): the row LAYOUT regenerates when the scale's degree COUNT changes or via the Strings tab's "Regenerate from scale"; hand edits otherwise stand. **The tarab pool is pitch-sorted with ONE string per pitch (2026-07-26)** — `InstrumentState.normalizeStrings` enforces it on every entry path (doubling-era documents fold in place, drone mappings follow the surviving twin), the UI rejects duplicate-pitch edits, and the historic Sa/Pa doubling rows folded into their strongest twins (`TarafRemovalParityTests` deliberately re-blessed). **The string-table law is RETIRED** — the fitted Pilu table's per-string detunes can't be expressed as scale degrees, the artifact was deleted, and `TarafRemovalParityTests` was re-blessed on the generated JI-grid default (git history has the fitted artifact + measurements).
- **ONE naming: the scale labels its own pitches (2026-07-25).** Wherever a pitch is named — Fret Pad frets, drone buttons (Mac + iPad), the Strings tab's degree dropdown and its drone mapping — the text is the scale point's own `label` (`PitchPoint.displayLabel`, blank → the ratio), never a second vocabulary. Two helpers in `ScaleDegrees.swift`: `scaleLabel(degree:octave:degrees:)` when the degree index is known (exact — prefer it), `scaleLabel(forRatio:degrees:)` when only a ratio survives (nearest degree in any octave). Octave repeats add `'`/`,` (`octaveMarked`). Rename a degree in the scale editor and it renames everywhere. Concert note names (`Scale.noteName` / `NoteName.name(forMIDI:)`) are a different axis — they label absolute Hz in the tuning readouts, not scale degrees. Guard: `ScaleLabelTests`.
- **Autonomous audition.** `AuditionRunner` watches `<repo>/auditions/inbox/` for `*.json` scores; WAVs land in `<repo>/auditions/outputs/` with a `.done` (or `.error`) marker. **Writers must use atomic writes** (`*.json.tmp` → `mv`) — the runner waits for size-stable files but a non-atomic writer still races. `tools/audition_iterate.py` does this; **bash heredocs do NOT**. Score format: [docs/simulator.md](docs/simulator.md).
- **`InputDimension`** (was `Dimension`) — renamed to avoid clashing with `Foundation.Dimension` once both modules are visible.
- **Where ranges live.** `Config.swift` holds system-level constants only. Every instrument parameter's range lives in **`ParamRegistry.swift`**; tilt-binding endpoint ranges come from the target (`MapTarget.defaultRange` in `TiltMapping.swift`).
- **`Scale.swift`** owns 12-TET frequency / note-name helpers. **Always use `scale.frequency(for:)`, never hardcode 12-TET formulas.** The playing scale is a `PitchScale` (JI ratios); the tarab table stores scale-degree references into it (`InstrumentState.scaleRatios` mirrors the pad's degree ratios via the scale push).
- **Log-frequency space.** All pitch interpolation uses `log2(freq)` — perceptually linear movement.
- **One touch = one wire identity, full-resolution pitch.** Each touch gets a namespaced u16 wire id in `OutboundPlayState` and its pitch travels as f32 fractional MIDI (~0.0008¢) — no channels, no note+bend split, no 15-voice wire cap (2026-08-14; MPE round-robin is history). The Mac has no poly toggle — the voice's polyphony is `bow_live_poly` gut strings on one shared bridge (poly-as-physics), slot-allocated in `BowControlMapper` by `.touch` keys (wire) and `.midi` keys (in-process) under identical laws. **2026-08-19: the per-touch velocity byte is real** — the iPad fills it with its accelerometer strike estimate (`MotionSource.strikeVelocity01`, trailing-window, no onset delay) and the mapper stores it per slot for the String voice's `bow_attack_vel` velocity→attack-sharpness law (0 default = inert, the parity contract; `bow_settle_sharp` likewise exempts sharp attacks from the settle). Registry defs for artifact-absent rebuild keys must equal the ENGINE fallbacks (`ParamUnificationTests.testAuthoredDefaultsMatchEngineFallbacks` — the Parameters tab once showed attack bite 2.0 while the engine ran 0).
- **Hot path:** use `cachedParamValue(for:voiceIndex:)` — **never** the dictionary-based lookup.
- **Producers write state; the link paces the wire.** Touch/motion handlers do O(1) locked writes into `OutboundPlayState` (main thread); `TarabLink`'s 120 Hz `DispatchSourceTimer` on its own `userInteractive` queue emits ≤1 fresh frame per tick — main-thread stalls cannot delay the wire, and there is no per-touch bend re-send loop (glide continuity = the Mac's 9 Hz meend smoother). The played pitch tracks the finger directly via `pitchAt`. The automatic vibrato LFO was removed — **vibrato is a playing technique** (move the finger).
- **Audio thread** (Mac) runs the `StringVoiceSource` render block, pulling from the kernel under the source's own lock. It **never** does MIDI or state logic.
- **SwiftUI updates are throttled** to ~15 Hz via manual `objectWillChange.send()` on the iPad's `NoteManager`.

## Building

From the repo root:

```bash
./tools/build-mac.sh
```

Wraps the macOS build, filters non-actionable noise, exits non-zero on errors, and regenerates `docs/parameters.md` + `docs/html/`. Wire it into a pre-commit hook or CI step so a refactor that breaks `TarabdaarMac` while iOS still compiles is caught before merge.

Tests: `cd Packages/TarabdaarCore && swift test`. The parameter-system regression guards live there (`ParamUnificationTests`, `RebuildCostTests`, `ParamLivenessTests`, `LiveParamPushTests`, `ZipperTests`, `RealtimePerformanceTests`, `PresetCodingTests`, `TarafRemovalParityTests`), alongside the scale guards (`TarabRatioTests`, `DroneStringTests`, `ScaleLabelTests`).

The iOS target builds with the standard `xcodebuild -scheme Tarabdaar` invocation against an iPad simulator destination; `-showdestinations` lists the available names, which vary by machine.

**A physical device is required** for accelerometer, gyroscope, and MIDI output.

## Sound Design Iteration

The voice's physics were fitted offline (in the since-decoupled `~/Desktop/sarangi` project) and ship as `bowed_string.json`. Tarabdaar does not re-fit; it edits the fitted values. (The exact fitted Pilu STRING table is gone — since the 2026-07-25 scale centralization the tarab is generated from the centralized scale.) To change the sound:

- **Parameters tab (⌘5)** — every parameter in 14 filterable groups (10 voice — the Tanpura group joined 2026-08-04, the Fret linger group 2026-08-18 — + the 4 FX points), each row with a mapping button. `rebuild` rows persist as an override dict and re-apply through a crossfaded off-main rebuild; `live`/`hybrid` rows apply instantly. "Default (Sarangi Live)" / "Reset all" clears everything; double-click a row label resets one.
- **Strings tab (⌘2)** — the sympathetic strings and their tuning. Since the taraf simplification these rows feed the modal-jawari block only, so a row its selection does not pick up is inert. The Drone buttons section also holds the **drone Voice picker** (Tanpura default / legacy sympathetic swell).
- **Live tab (⌘1)** — the **Instrument picker** (String / Tanpura) for the played voice, above the MIDI status and performance graphs.
- **Controls tab (⌘4)** — tilt bindings and composite macros, driving any parameter live.
- **FX tab (⌘6)** — the four-insert FX rack (graphic EQ + Bigverb/Room reverb at voice→taraf, voice, taraf, global; all `.live` registry params `fx_<point>_*`, off by default = byte-null). See [docs/fx.md](docs/fx.md).
- Audition path for scripted sweeps: `param.<key>` or `string.<key>`.

**LEVELS — the non-obvious part:** calibration lives inside the fitted preset (`bow_live_trim` / `bow_rev_*`; since 2026-08-23 `bow_gain` — def 1 = bit-exact — multiplies the trim as the PERFORMANCE master volume of the whole radiated instrument, the knob that actually moves total loudness where expression can't because the taraf keeps ringing), and the Mac pads hold a flat **CC11 = 32** — the fitted expression median. CC11 is a real ±16 dB loudness axis here, not a trim. Loud peaks are backstopped inside the kernel, and a **linked-stereo safety limiter** (`bow_lim_thresh`/`bow_lim_rel_ms`, 2026-08-01) rides the very end of the chain — bit-exact below its 0.8 ceiling, so parity is untouched. Kin notes (hard-struck Sa/Pa: voice + jt ring + coupling return add coherently) are the hot spots; **`bow_jt_norm`** evens that at the CAUSE (long-ring anchor rows charge hotter — 0.6 measured near-even across degrees), the limiter is the safety net.

**Presets** save/load as ONE `TarabdaarPreset` document (2026-07-30) covering the whole rig — sarangi doc + physics + param values + composites + tilt bindings. **No file panels**: Save preset… asks only for a name, the preset lands in the app-managed library (`PresetLibrary`, `Application Support/Tarabdaar/Presets/`, one `.tarabdaar` file each) and appears in the Load-preset menu automatically, under the factory default (a full-rig reset). Every section is optional, so split-era/legacy files dropped into the folder still load, applying only what they carry. Details and traps: [docs/sound-design.md](docs/sound-design.md).

**To make a change the shipping default,** edit `bowed_string.json` in `Packages/SarangiKit/Sources/SarangiKit/Resources/` (the physics) or the builders that generate the tarab (`RagaTuning.buildSpecs` for the layout), and re-run the tests — `TarafRemovalParityTests` will fail, which is the signal to re-bless its hash deliberately rather than by accident.
