- [Fret Pad](docs/fret-pad.md) - **The sole playing surface** (Mac tab ⌘4 + the iPad's only surface). Each scale degree is one or more vertical **fret segments** positioned **freely** (2026-07-23 free-fret change: a fret's `x` is its own layout state, unrelated to its pitch; the played pitch is the continuous **fret field** — `fretFieldLog`: linear log-pitch x-interpolation between the two closest fret columns, each column y-resolved — exact on a fret, r/R-style stacked variants blend by y); **onset-only snapping** — a touch starting within the Snap distance of a fret AND inside its vertical extent snaps to its exact pitch, starting elsewhere approaches the note through the field, and drags glide continuously (constant log-offset from a snapped onset — never re-snaps); `bow_drone_comp_cents` 15.5) — the target nominal = request ÷ that shift; an existing row within ±6c of target is reused, else a dedicated string is appended (median gain/t60); presses map via `BowEngine.droneRow(forRequestedHz:)` (pitch-class first). Verified within ~±4c of request. ## Key Conventions

> **Read this first — the app is now a single-voice instrument.** Two rounds of deletion define the current shape:
> **(1) 2026-07-23 simplification:** the **Tanpura, Sitar, Harmonics, Simulator, Chord Pad, String Pad, and Pitch Pad tabs are DELETED**, along with the whole `StarpadDSP` package (`TanpuraModel`/`TanpuraParams`/`TanpuraString`/`SitarParams`/`tanpura-render`/DSP tests), all tanpura/sitar code in `AudioEngine`, the sitar base voice, the `chordPad`/`stringPad` engines + `stringArrangement`, the `tools/{tanpura,sitar}_*.py` tools, and the iOS Pitch/Chord/String surface views.
> **(2) 2026-07-24 SWAM strip:** the **entire SWAM / hosted-AU host, base-voice selection (`BaseVoice`/`SwamInstrument`/`SoundPreset`/`ViolaBodyBand`), the coupled bridge–body network (`SarangiProcessorAU`, the inline `sarangiEffect`, `SarangiEngine.renderSample` usage, `hostedDriveTap`, `sarangiDriveGain`), the FX tab (`FXView`/`GraphicalEQView` + 25 network params + spectrum rings via `SpectrumProvider`/`SpectrumAnalyzer`), the body/viola EQ + master reverb/filter room, and `MappableMacParam` CC mappings are DELETED**. The **sarangi String voice (`StringVoiceSource`/`BowEngine`) is the ONLY voice**; the audio graph is just `stringVoiceSource.node → symGain → mainMixerNode → output`.
> **`IPadSimulator` + `AuditionRunner` were KEPT (headless)** — the audition inbox→WAV pipeline still runs; only the Simulator TAB is gone. **The Fret Pad is the only playing surface**, and it hosts the scale selector + list editor + editable tonic (`ScaleListEditor` in `FretPadView.swift`), editing the still-alive `AppController.pitchPad` scale model. Mac tabs are now **Live ⌘1 · Tarab ⌘2 · Fret Pad ⌘3 · Controls ⌘4 · Parameters ⌘5 · Setup ⌘6** (Controls = tilt bindings + composite parameters; Parameters = the ONE parameter list). **(3) 2026-07-24 PARAMETER UNIFICATION:** the **Sarangi tab is DELETED** — its physics sliders merged into the Parameters tab (which also inherited its preset toolbar), and `StringParamsView`/`SarangiEditorView`'s editor + the iOS `CurveEditorView` are gone. **Some bullets below still describe removed systems — treat this banner as authoritative where they conflict.** **2026-07-24 remnant audit:** `StringPadGeometry.swift`, `ChordPadGeometry.swift`, `StringArrangementStore.swift`, the `StringArrangementSysEx`/`StringArrangementSyncStore` pair, and the iOS `ScaleEditorView.swift` are now DELETED. The symbols the Fret Pad still needed from them (`scaleDegrees`, `sargamName(s)`, `Temperament`, `ScalePreset`) moved to **`ScaleDegrees.swift`**. `PadLayout`'s non-fret cases remain on purpose — the sync blob encodes the layout, so the raw values must stay stable.

- **Two devices, one cable, almost no shared state**. iPad is a MIDI controller (USB-MIDI only — no Bonjour/Wi-Fi). It owns its glide/vibrato params, calibration, and the MPE emission. Mac is the **sarangi String voice** (`SarangiKit.BowEngine` + `CBowKernel`). It owns the String physics state, the tarab tuning, and the composite/tilt bindings. The two communicate only over the USB cable. **Do not introduce shared params** beyond the one documented exception below — if a feature wants to live on one side, all its state lives on that side.
- **The one exception: pad sync (Mac → iPad over SysEx).** StarpadMac edits; Starpad performs. The Mac pushes a `SyncedScaleState` (the `PitchScale` **plus `tonicMidi`, `marginPixels`, and the active `layout`**; since the 2026-07-23 simplification the layout is always `PadLayout.fretPad` — the `PadLayout` enum keeps its other cases for blob compatibility but only Fret Pad exists on either side) to the iPad as a MIDI **SysEx** blob on the same USB cable: `PitchScaleSysEx.encode` = `F0 7D 01 base64(compact-binary) F7` (kept small so it clears the iOS USB-MIDI SysEx bridge; blob `version` is now `3`). The iPad's `ScaleSyncReceiver` receives it via an **input port connected to every source** (USB-incoming MIDI arrives as a *source* on the iPad — a virtual destination does NOT catch it) plus a virtual destination as backup, reassembles SysEx across packets/callbacks, and calls `PitchPadEngine.applySyncedState` (swaps scale/tonic/margin/layout). It persists to `SyncedScaleStore` (UserDefaults) for offline relaunch. One-way; the iPad has **no** scale editor and its tonic is read-only. Push is driven from `AppController` via Combine: `Publishers.MergeMany` of `pitchPad.$scale` / `$tonicMidi` / `$marginPixels` / `fretPad.$marginPixels` / `$fretArrangement` / `$ipadLayout` / `midi.$destinationCount`, debounced, → `MIDIEngine.sendSysEx(_:toDestinationsMatching: "Starpad")` (falls back to all destinations if the name matches none — the bridged iPad endpoint shows up as "iPad", not "Starpad Scale"). **Second SysEx message:** the Fret Pad's segment layout is its own state (not derivable from the scale), so the Mac ALSO pushes `FretArrangementSysEx.encode` = `F0 7D 03 base64(…) F7` (subtype `0x03`) into `@Published fretArrangement` (persisted via `FretArrangementSyncStore`). (`StringArrangementSysEx` `F0 7D 02` and its sync store were DELETED 2026-07-24 in the remnant audit — subtype `0x02` is simply unused now.) **The fourth SysEx (TiltMappingSysEx, 0x04) was DELETED 2026-07-24 with the dead-param cleanup**: the iPad no longer evaluates ANY parameter mapping (its MAP editor + `NoteManager` binding caches are gone) — it streams only the raw tilt report (`TiltAxisWire`) and the Mac evaluates its own `tiltMapping` (`AppController.applyTiltAxis`). These (0x01 scale + 0x03 fret arrangement) are the **only** SysEx and the **only** cross-device state in the app.

The simulator's `MIDIEngine` uses `publishToCoreMIDI: false` and an in-process `onLocalEvent` callback to deliver MIDI directly into `AudioEngine.sendHostedMIDI` + `AppController.handleSimulatorCC`, so it never feeds `MIDIInput` and coexists with a plugged-in iPad.
- **Fret Pad tab (Mac ⌘3; the sole playing surface, runs on the iPad too).** A free-fret surface (`StarpadMac/Views/FretPadView.swift` + `Packages/StarpadCore/.../FretPadGeometry.swift`): each enabled scale degree is one or more vertical **fret segments** positioned **freely** — since the **2026-07-23 free-fret change** a fret's `x` (0..1 across the base band) is its own layout state, NOT derived from its pitch, and the played pitch is the continuous **fret field** (`fretFieldLog` + `fretColumnLog`: a **column** = frets sharing an x within `fretColumnEps` 0.5 px, e.g. the stacked r/R pair; the column's pitch at the touch's y = exact inside a member fret's extent, linear y-interpolation across the gap between stacked frets, clamped beyond; the field = the linear log-pitch **x-interpolation between the two closest columns** (nearest at-or-left, nearest right; past the outermost columns the outermost pair's line EXTRAPOLATES — edges keep the local slope) — continuous everywhere, and pitch always moves TOWARD the neighbor being dragged at. Earlier same-day revisions used global inverse-distance blends over every fret — the far tail collectively outweighed the nearest fret and dragged gaps toward the layout's mean pitch, e.g. rising left of Sa; two-column interpolation removes that failure class). The base layout sits in a central band; the surface extends `ghostExtentOctaves` band-widths past it each side, tiled with read-only octave-repeat ghost copies of the whole layout (left = octave down, right = up; `fretPixelX(forBandX:)`/`fretBandX(atPixelX:)`; toolbar "Octave ±" 0–2 in 0.25 steps, **fractional**, default **0.5**). **Onset-only snapping**: a touch that STARTS within the Snap distance (px, the repurposed `engine.marginPixels`, 0–64; **Fret Pad default 24** set in `AppController.init` — fitted to iPad onsets (worst observed 14.9 px; < the 40 px min fret gap), other pads keep the engine's 16; 0 = fretless) of a fret AND inside its vertical extent snaps to that fret's exact pitch (`fretSnap`); starting above/below the extent (or in open space) plays the field pitch — the **approach path**. Drags NEVER re-snap discretely: pitch = `2^(fieldLog + snapOffsetLog + assistCorrection)` where `snapOffsetLog` is the constant log2 delta captured at a snapped onset (exact at onset, meend/vibrato relative to it, cleared on note-off) and `assistCorrection` is the **drag assist** (`FretDragAssist`, StarpadCore, 2026-07-16, **constants FITTED to real iPad playing** — see fit provenance in docs/fret-pad.md): a gated magnetic correction — slewed toward the nearest fret at rate = gate × proximity × settle, where gate = min(1, max(stationarity(smoothed |dx/dt|, 1 below 59 px/s → 0 above 375, τ 26 ms), **turnGain 2.0 × direction-flip impulse** (deadbanded dx sign change fires impulse=1 decaying with turnTau 26 ms — fast connected turns (~30 ms) are invisible to any speed average; the flip is causal with ~1-event latency))), proximity = within the **assist basin = radiusScale 1.75 × Snap = 42 px at the 24 px default** in SCREEN px — distance to the fret line's x (since the free-fret change; the constants were fitted on the old pitch-mapped ribbon — refit from fresh recordings; fast landings are ~2× sloppier than the onset radius; onset snap stays 1×) AND the fret's y-extent (full pull inside half the basin → 0 at the edge), settle τ 5 ms **bounded by a hard slew cap ≈ 1500 ¢/s** on the correction ⇒ smoothness by construction. Stops land exactly on the fret, fast turns get pulled onto it as the note speaks, fast transit/vibrato is untouched, and with no qualifying fret the correction FREEZES (carried tuning anchor — never decays mid-hold). Fit result on the 8×9-note phrase recording: landing error 39.7¢ → 29.3¢, transit warping ~2¢; the recording covers fast connected playing only — refit with slow glides/vibrato to regularize (high speedCeiling makes slow glides sticky near frets). Stops emit no events ⇒ a 60 Hz Timer per surface drives `tick()` → `engine.glide` while touches are down (timer closures capture only engine+assist, never the view struct; it also runs while a legato release is pending and self-invalidates when idle — iOS re-arms on `assistTimer?.isValid != true`, NOT nil-check). **Tap legato** (`FretLegato`, StarpadCore, toolbar "Legato" toggle, default ON, carried as `FretArrangement.legato` → store doc / SysEx blob flags byte): for very fast phrases the player TAPS notes instead of dragging — a tap while the previous note sounds (or within the ~120 ms release grace window; owner releases are DEFERRED that long) takes the voice over via `PitchPadEngine.transferTouch(from:to:)` (ownership moves with NO MIDI events — one articulation, bends only = true legato; returns false on stale state → caller falls back to fresh noteOn) and **glides** old→new pitch over ~50 ms as an additive smoothstep offset on top of the assist output (starts at exactly the old pitch ⇒ no discontinuity). Mono last-note priority while on (stolen touches' noteOff no-ops post-transfer). The assist constants are **fittable to recorded real playing**: the **Rec/REC** toggle (Mac toolbar + iPad `PadToolbarIOS`; `FretGestureRecorder`, StarpadCore) appends play strokes as JSONL (`[t,x,y,u,o,tick]` events + fret-context snapshot) to `~/Library/Application Support/Starpad/FretRecordings/` (Mac) or the app's `Documents/FretRecordings/` (iPad — user-visible via `UIFileSharingEnabled`/`LSSupportsOpeningDocumentsInPlace` in `Starpad/Info.plist`; copy to the Mac via Finder's device browser to fit — **the iPad fit is what matters**, finger ≠ mouse dynamics); `tools/fretpad_fit.py` (`report` = stats + Swift↔Python parity check on the recorded `o`, `fit` = hindsight-label dwells/reversals then grid+coordinate-descent the 4 causal constants, `--phrase "p n d n p d m p g"` = protocol mode aligning inflections to a KNOWN repeated svara sequence by monotonic DP — better labels than nearest-fret for scripted sessions, `selftest` = synthetic pipeline check incl. the phrase aligner) prints values to bake into `FretDragAssist.swift`. A `FretSegment` = `degreeIndex` (into `scaleDegrees(from: pitchPad.scale)`, looked up live via `fretRatio` — a vanished degree skips, not deletes) + free `x` + `topY`/`bottomY` (the snap zone; editable by dragging endpoint handles, min height 0.02) + `enabled`; default layout (`FretArrangement.defaultArrangement`) mirrors the old String Pad: **7 evenly-spaced columns** (`x = (col + 0.5)/7`; S · R/r · G/g · m/M · P · D/d · N/n) with the svara split at **half-size bands pulled toward the vertical center** (lines 1.5 px base / 1 px ghost, glow half-width 2.5 px, shift-click add height 0.15) — S/P centered (0.39–0.61), shuddha lower-middle (0.565–0.755, center 0.66), komal/tivra upper-middle (0.245–0.435, center 0.34 — the String Pad's paired-key centers). Edit mode: drag line = move (BOTH axes — x clamped to the base band), drag endpoint = resize, shift-click = add a fret at the click, on the degree nearest the field pitch there (circular in the octave; multiple segments per degree OK), right-click = delete, empty space = play; **Perform** hides band gridlines/labels/handles and styles ghosts like base. The **`AppController.fretPad` `PitchPadEngine`** (`init(audio:)`, tonic sink, `macExpressionLevel`) is the MPE emitter. Sounding glow via `fretFillCells` (thin-rect `VoronoiCell`s → `CellFillsView`); glide glow = nearest fret within Snap at the cursor's height, distance-faded (display-only). Persisted via `FretArrangementStore` (`FretArrangements/_Current.json`, debounced autosave, atomic writes, ids minted on decode; doc **v4** = free x — pre-v4 files/blobs are REJECTED and the default is rebuilt). **Runs on the iPad** (`FretPadViewIOS`/`FretPadSurfaceIOS` in `PitchPadView_iOS.swift`, always perform mode, per-touch `snapOffsets` — fully multitouch): selecting the Mac tab sets `ipadLayout = .fretPad` (fourth `PadLayout` case) and the arrangement rides the **third SysEx message** (`F0 7D 03 …`, `FretArrangementSysEx`, subtype `0x03`, blob **v5** — per-segment 14-bit x + the 4 drone ratios as 14-bit cents) → `ScaleSyncReceiver.fretArrangement` (persisted via `FretArrangementSyncStore`; never-synced fallback = `defaultArrangement` from the synced scale); the synced `marginPixels` carries the Snap distance while active. See [docs/fret-pad.md](docs/fret-pad.md).

Shipped composites: **Taraf Purity** (slot0, `bow_taraf_jawari` 1.3→0 + `bow_jt_lp` 16000→1500), **Taraf Decay** (slot1, `bow_jt_damp` 0→1), **Tone Tilt** (slot2, `bow_tone_tilt` −1→1), **Expression** (slot3, `bow_expr` 0→0.5). Default tilt bindings: tilt1→Purity+Expression, tilt2→Decay, tilt3→Tone. Audition `voiceParam`s: `param.<key>`/`string.<key>` (any parameter) + `stringPurity`/`stringTarafDecay`/`stringToneTilt` (→ slots 0-2) + `composite1..8`. **Adding a parameter = ONE `ParamSpec` entry** — it shows up in the Parameters tab, the composite menu, the tilt menu and the docs automatically. **REBUILD COST (measured 2026-07-24, `RebuildCostTests.swift`):** a `.rebuild` edit builds a fresh `BowEngine` off-thread — **~218 ms**, of which tables+kernel+pool are **4.5 ms** and the **settle pre-roll is 98%** (`StringVoiceSource.settleBlocks`, cut 6→4 blocks; the jt web's idle chime asymptotes near −50 dBFS so blocks 5-6 bought ~1 dB for ~110 ms). `setEngine` now **equal-power CROSSFADES** the outgoing engine out over `engineCrossfadeMs` 300 ms — without it a rebuild during the ring left **4.9%** of the taraf+room tail (it is engine state); with it, **69%**. Costs 2× voice CPU for the fade window only (11%→19% of realtime at the app's 128-frame buffer). A held note was never the problem (96% of level within 43 ms even on a hard swap). **Do NOT try to fix the pre-roll with a longer fade** — measured, 180→450 ms bought 1 dB; the residual is the web's steady idle floor, so the real fix is an upstream `q0` that doesn't leave it charged. **IN-PLACE PARAMETERS (2026-07-24, stages 1+2 — most edits no longer rebuild):** `BowEngine.setLiveParams(bp:scalars:)` pushes an edit onto the RUNNING kernel — the 61 per-sample scalars via the NEW vendored-C divergence **`bow_set_scalars`/`bow_poly_set_scalars`** (same pattern as `bow_set_jaw_gain`; re-apply on re-vendor) + `BowControlFilter.updateLiveParams` for the mapping constants + outGain/reverb/radiation. NOTHING resets (string histories, taraf ring, jawari web, room tail, articulation all carry). `ParamRegistry.inPlaceKeys` = the **58** shipped keys (stage 3 added the body modal bank + jawari tables via NEW C `bow_[poly_]set_body` / `bow_[poly_]jt_set_coeffs` — coefficient arrays overwritten in place, HISTORIES KEPT: body resonator state → click-free, jawari wrap → relaxes into the new geometry; `bow_jt_load` is init-only and MALLOCS, never call it twice). Still rebuilding: the sympathetic web (`bow_taraf_damp/inharm/pol_cents` move DELAY LENGTHS; `bow_taraf_Z/bright/gain` ride the per-voice arrays incl. the charge window init consumes but doesn't store) + `bow_body_modes`; `StringParamStore.pushNow` tries `AudioEngine.applyStringVoiceOverridesInPlace` and falls back to a rebuild. Empirical classification (`ParamLivenessTests`): 22 kernel-scalar + 31 no-table + 13 coefficient-array (body bank + jawari tables) = **58 in place**; the 7 left on the rebuild path are the sympathetic web's 6 + `bow_body_modes` (the only truly structural one). Verified: pushed value settles within 0.03 dB of a baked rebuild; held note keeps 100%, ring 76% (hard swap 4.9%). **ZIPPER (measured, `ZipperTests`):** none at tilt rate (60 Hz sweeps −2.0…+0.1 dB excess HF — friction coefficients change how the string EVOLVES, not the current sample). Clicks come only from large INSTANT jumps of signal-multiplying params: a +17 dB `bow_live_trim` jump measured **17.9×** the signal's own sample-to-sample motion → 25 ms chunk-rate ramp got it to 3.4× → **per-sample `outGain` interpolation in postChain** got it to **0.0×**. BOTH needed. The ramp also CAPS the render chunk to 256 frames while active (`liveRampArmed`, armed on the control thread) — a 4096-frame offline/audition call would otherwise resolve the glide in one step. Goldens stay bit-exact (dg = 0 when the gain is unchanged). **TRAP the no-op test caught:** the ramp's 256-frame CHUNK CAP is NOT neutral — chunk size sets the control-interpolation grid + jt block boundaries, so splitting a 4096-frame offline render moved the chaotic friction loop **41% of peak on a push that changed NOTHING**. Fix: arm the ramp only when a ramped quantity actually moved (coefficient-only reloads never arm it). `testNoOpPushIsBitIdentical` guards it. A real edit still splits chunks, which is why a pushed value lands within ~0.4 dB of a rebuild rather than exactly on it. A jawari-table CACHE was tried and REMOVED: `buildJawariTables` is only 3.4 ms. Since rebuilds are now crossfaded, **no UI labels the apply strategy** — it is a routing hint (still can't sweep at 60 Hz tilt rate). Regression guards (`swift test`): `Packages/StarpadCore/Tests/StarpadCoreTests/{ParamUnificationTests,RebuildCostTests,ParamLivenessTests,LiveParamPushTests,ZipperTests,RealtimePerformanceTests,PresetCodingTests}.swift`. ## Adding Files to the Xcode Project

**For files in `Packages/StarpadCore/Sources/StarpadCore/`** — drop the `.swift` file in that directory. SPM auto-discovers it; no pbxproj edit needed. Make sure types/init/methods used outside the package are `public`.

1. Add a `PBXBuildFile` entry (`A1xxxxxx` for iOS, `C1xxxxxx` for macOS)

4. Add to the appropriate `PBXSourcesBuildPhase` files list (iOS: `A7000001`, macOS: `C7000001`)

Use sequential IDs following the existing pattern.

## Sound Design Iteration

The played voice is the **String instrument** (`SarangiKit.BowEngine` + `CBowKernel`, driven by `bowed_string.json`; taraf tuning = the Tarab tab rows, physics/room/level = `bow_*` artifact keys, overridable via audition `string.<key>` or `AudioEngine.setStringVoiceOverrides`). It was fitted **offline in the separate `~/Desktop/sarangi` project**; Starpad **vendors the fitted DSP package** and does not re-fit. To change the sound from inside Starpad:

- **Edit live in the Parameters tab (⌘5)** (`ParametersView` over `ParamRegistry`): the preset toolbar (`InstrumentPresetToolbar`, still in `SarangiEditorView.swift`) + **every** parameter in 8 filterable groups, each row with a mapping button (bind to a tilt / add to a composite). `.rebuild` rows ride a persisted override dict `starpad.stringOverrides.v1` → `AudioEngine.setStringVoiceOverrides` → debounced off-main `BowEngine` rebuild; `.live`/`.hybrid` rows apply instantly. "Default (Sarangi Live)" / "Reset all" clears overrides AND resting values; double-click a row label resets one. The **sympathetic strings + tuning live in the Tarab tab (⌘2)** (`TarabView`) — auto-sync to the scale starts OFF (String-era default; the fitted Pilu table sticks) and is opt-in via the tab's switch. **Tilt / composite parameters** (Controls tab ⌘4) drive any parameter live.
- **LEVELS:** calibration is inside the fitted preset — `bow_live_trim` / `bow_rev_*` set the output level; the Mac pads hold flat CC11 = **32** (the fitted expr median — CC11 is a real ±16 dB loudness axis here). Loud peaks are backstopped inside the kernel.
- **String params** (the played voice; `ParamRegistry` groups): **Body (formula modes)** `bow_body_*`/`bow_yinf`/`bow_kret`; **Bow & string** `bow_mu_*`/`bow_v0`/`bow_Zt`/`bow_gut_*`/`bow_nut_fc`/`bow_br_fc`/`bow_noise*`/`bow_tors_*`/`bow_age_*`/`bow_cr_*`; **Playing ranges** `bow_v_lo/hi`/`bow_live_beta_*`/`bow_live_press_*`/`bow_expr_lift`/`bow_f_cap`; **Jawari taraf** `bow_jtaraf_on`/`bow_jt_*`; **Taraf** `bow_taraf_*`/`bow_open_*`; **Articulation** `bow_place_ms`/`bow_draw_*`/`bow_attack_*`/`bow_vib_*`; **Radiation & output** `bow_rad_*`/`bow_w`/`bow_live_trim`/`bow_rev_*`/`bow_st_*`/`bow_tone_tilt`; plus the **Bow stroke** group `bow_expr`/`bow_press`/`bow_pos`/`bow_tilt`. Audition path `param.<key>` or `string.<key>` (routes through `setParamValue` → shows in the UI + persists).
- **Preset**: **"Default (Sarangi Live) — Pilu, fitted"** (`SarangiStore.loadSarangiLiveDefault` + `StringParamStore.resetToDefault`) = the upstream default instrument exactly: untouched `bowed_string.json` physics, the EXACT fitted Pilu string table, Sa 328.9 Hz, auto-sync OFF. It is the ONLY preset and the fresh-install default.
- **Persistence + PRESETS (2026-07-24)**: `SarangiStore` auto-saves the `InstrumentState` (`starpad.sarangiState.v8`); String overrides `starpad.stringOverrides.v1`; resting param values `starpad.controlDefaults.v1`; composites `starpad.compositeParams.v1`; tilt bindings `starpad_dimensionMapping_v6`. **They save/load as TWO SCOPED presets** of one `StarpadPreset` document (`PresetScope` .instrument / .controls / .all): **instrument** = `.starpad` (sarangi doc + physics + `paramValues`, Parameters tab) and **controls** = `.starpadmap` (composites + `tiltMapping`, Controls tab). Split deliberately — a sound and a tilt mapping are independent, so loading one never clobbers the other. `capturePreset(name:scope:)` / `applyPreset(_:scope:)` filter by scope, so an older COMBINED file loads from either place applying only that half, and `sections(in:)`/`isEmpty(in:)` let the toolbar say "that's a controls preset" instead of silently doing nothing. — `StarpadPreset` (`Packages/StarpadCore/.../PresetDocument.swift`; it is DATA, not UI, hence the package) with `AppController.capturePreset/applyPreset/savePreset/loadPreset`, driven from the Parameters-tab toolbar (`InstrumentPresetToolbar`). **The sarangi preset is FOLDED IN** — there is no separate `.sarangi` save any more, though old `.sarangi` files (a bare `InstrumentState`) still LOAD via `StarpadPreset.decode`'s legacy fallback. Every section is OPTIONAL: a tilt-bindings-only preset is valid and leaves the instrument alone. Traps: a tilt binding survives only through its `MapTarget.storageKey`, and unknown `param:` keys are dropped on load (`DimensionMapping.pruned`); `StringParamStore.replaceOverrides` clears `dirtyKeys` to force the REBUILD path (a preset can move keys that resize tables). Guards: `PresetCodingTests.swift`. To make a change the shipping default, land it upstream in `~/Desktop/sarangi` (params/bowed_string.json / sarangi_pilu.json / sarangi_coupled.json) and re-vendor the resources.

To re-fit the model or change its DSP, work in `~/Desktop/sarangi`, then re-vendor `Packages/SarangiKit/Sources/SarangiKit/{DSP,Model,Violin,Bow}` + `Sources/CBowKernel` + the resources (recopy `params/bowed_string.json`, `params/sarangi_model_v57.json`, `params/sarangi_coupled.json`, `params/live_comp.json`, and `app/Sources/SarangiState/Resources/sarangi_pilu*.json`; re-apply the Starpad divergences listed under the SarangiKit package bullet — incl. the MPE sections in `Bow/BowControls.swift`). The coupled artifact carries its own 44.1 kHz radiation FIR (`N_rfir`) — no more Starpad-side FIR re-bakes. Don't fork the DSP into Starpad.
